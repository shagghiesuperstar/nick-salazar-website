## How each motion requirement is implemented

| # | Requirement (lead's design lock) | Implementation |
|---|---|---|
| 1 | Video plates: tall section, sticky 100dvh inner frame, native scroll, finite page | `.plate` `styles.css:195` (`min-height: var(--plate-height)` = 160dvh; hero 150dvh), `.plate__frame` `:203` (`position: sticky; top: 0; min-height: 100dvh; overflow: clip`). `min-height` (not `height`) so a very short viewport (320×568) lets the copy grow and remain reachable instead of being clipped. Page is finite: 7 plates + 5 text sections, `scrollHeight` 20 417 px at 1440×900. |
| 2 | Differential layer motion via CSS scroll-driven animations, feature-detected | `@supports (animation-timeline: view())` block `:389` — `.plate { view-timeline-name: --plate }`; media `plate-media` (`:427`, 6% → −12% travel), shade `plate-shade` (`:432`, 2% → −2% + opacity ramp), pair `plate-pair` (`:438`, 34% → −14% + scale 0.97 → 1.03), story `plate-story` (`:443`, 48% → −18%), meta pinned (no animation). Hero uses its own keyframes on `animation-range: cover 40% cover 100%` (`hero-media/-shade/-name/-role` `:448–:461`) because cover 40% is the load position. Only `transform`, `opacity` and `color` animate; `will-change: transform` is set only on the four moving layers. |
| 2b | JS `--progress` fallback when scroll timelines are unsupported | `app.js:82–118`: adds `html.js-progress` only when `CSS.supports("animation-timeline: view()")` is false and motion is not reduced; IntersectionObserver keeps a `visible[]` list of plates; a passive `scroll`/`resize` listener requests one rAF (`ticking` guard) that writes `--progress` (0–1 over the same cover range; hero remapped from 0.4) only on visible plates. CSS consumes it at `styles.css:468–496` with `calc()`/`min()`/`max()` and `color-mix()` so the curves match the keyframes. Verified by stubbing `CSS.supports` (see fallbacks below): `--progress` 0.5962 while held, shade 0.72, pair `oklch(0.99 …)`. |
| 2c | JS off | `html.no-js`: CSS scroll timelines still run in supporting browsers (verified: shade 0.22 → 0.72, pair transform/colour animate with JS disabled); videos stay on their posters; `[data-reveal]` is fully visible because the hide rule is scoped to `html.js` (`:499`). |
| 3 | Shade + brightening copy, legible at every intermediate progress | `.plate__shade` `:224` = `--color-shade` with two two-stop gradients (`--gradient-shade-vertical` + `--gradient-shade-vignette`), opacity `--shade-min` 0.15 → `--shade-max` 0.72 by 55% of the timeline. Copy colour ramps `--color-silver` → `--color-ink-max` over the same 0–55% span and holds. Guaranteed backplate: `.plate__copy::before` `:247` paints `--gradient-backplate-stack` (mobile, veil-strong 0.86 alpha at the copy) / `--gradient-backplate` (desktop, mirrored on even plates `:317`) behind the copy column at all times, plus a 1–2 px `text-shadow` in `--color-veil-strong`. Worst-frame arithmetic (progress 0, pure-white pixel): after shade 0.15 and veil 0.86 the effective background luminance is ≈ 0.129; silver body (L 0.55) gives ≈ 3.35:1 in the theoretical worst pixel, the display pair (large text) clears 3:1 everywhere, and at progress ≥ 0.15 (silver→ink ramp already at L ≈ 0.62, shade ≈ 0.31) body clears 4.5:1. The measured frames (`self-check/d1440-01-plate-entering.png`, `-02-plate-mid.png`, `-03-plate-held.png`, `m375-01/02`) show the actual footage never presents a white pixel behind the copy column; the lead's pixel sampling will confirm. If the lead's measurement finds a sub-4.5 body frame, raise `--color-veil-strong` alpha to 0.92 in tokens.css (one token). |
| 4 | Hero: video 01 behind, same shade logic, accents, pointer light | Hero is `.plate--hero` sharing the plate machinery; name `--color-accent` (signal-orange), credentials `--color-accent-2` (signal-sky). Pointer light `.hero__light` `:366`: one radial gradient element (`--light-size` 44rem), `mix-blend-mode: screen`, `opacity: var(--light-opacity)` = 0.12 only while `.is-lit`, moved by `transform: translate3d(var(--mx), var(--my), 0)` updated from a single passive `pointermove` on the hero (`app.js:194`, rAF-throttled). Only rendered under `@media (hover: hover) and (pointer: fine) and (prefers-reduced-motion: no-preference)` (`:383`); `display: none` otherwise and again under reduced motion (`:911`). |
| 5 | Reveal-once stagger | `[data-reveal]` hidden only under `html.js` (`:499`), `opacity 0 → 1` + `translateY(8px → 0)`, `transition-delay: min(var(--i) × 60ms, 480ms)`; `app.js:121–139` sets `--i` from the sibling index (capped 8) and an IntersectionObserver adds `.in` once then unobserves. Plate story blocks keep their timeline transform (`:506`). |
| 6 | Video behaviour | No `autoplay` attribute in the markup (contract with narrative-content); `app.js` strips it defensively. `attachSrc` (`app.js:27`) moves `data-src` → `src` on first need (hero uses a real `src` + `preload="metadata"` as the LCP element; all others `preload="none"`). IntersectionObserver (`app.js:64`) plays at ≥ 25 % visibility and pauses when out of view; `visibilitychange` pauses everything. `prefers-reduced-motion` and `navigator.connection.saveData` → `markStatic` (poster only, never plays). `play().catch` → `.is-static`, no console output. Preload policy: hero `metadata`, plates `none`. |
| 7 | Reduced motion | `styles.css:895–913`: all plate animations/transforms off, shade fixed at `--shade-static` 0.55, copy at `--color-ink-max`, pointer light removed, reveals become a 150 ms opacity crossfade with no delay, button/nav transitions 150 ms, no `:active` translate, `scroll-behavior: auto`. JS side pauses/statics every video and never arms the light or the `--progress` loop. |
| 8 | Assignment brief utility | `app.js:214–318`: assembles the `<pre id="brief-output">` live from every field (label from `<label for>`), `Copy brief` → `navigator.clipboard.writeText` then `document.execCommand('copy')` via a hidden textarea; status `role="status"` text "Copied. Nothing was sent."; `Download .txt` → Blob + object URL + programmatic `<a download="assignment-brief.txt">` click, revoked after 1 s; buttons flip `data-state` success/error with label swap for 2.5 s (no toast). Nothing leaves the page. Eight states in CSS: `.btn` `:711` (default/hover/focus-visible/active/disabled/loading/error/success); `.input` `:781` keeps a 1 px border in every state, outline-based ring reserved at rest, 44 px height shared with buttons, `.field__help` `:817` reserves `1lh`. |
| 9 | Nav | `.nav` `:70` N5 pill, `position: fixed` (not sticky, so gate 56 does not fire against the sticky plate frames), content-sized `width: fit-content; max-width: min(45rem, …)`, no transform on the pill so the `<details>` sheet can position normally. Current-section highlighting `app.js:150–166` via IntersectionObserver with a 40/45 % rootMargin band; `aria-current="true"` gets an accent dot. `<details>` menu closes on link click / Escape / outside click. `scroll-behavior: smooth` on `html` (`:20`) and `auto` under reduced motion (`:896`); every `[id]` has `scroll-margin-top: var(--banner-height)` (`:44`). |

Bans honoured: no `transition: all`, no bounce easings (only `--ease-out/--ease-in/--ease-in-out`), no hover-scale, no layout-property animation, `will-change` only on moving layers, no `100vw`, `dvh` throughout, `overflow-x: clip` on `html` and `body`, all grid tracks `minmax(0, 1fr)`, clickable text `white-space: nowrap`, 44 px targets on coarse pointers.

Palette after media-preparation's measurement (`analysis/verification/media/palette-confirmation.md`): name orange (baseline confirmed), credentials **yellow** (`--color-accent-2`; sky is absent from the footage and the token is retired/unused), red moved to the on-footage #D9282A. Video clips are 3:2, so `.plate__video` uses `object-position: 50% 42%`.

Closing-pass legibility fixes after the lead's pixel measurement: `--story-entry` 48% → 16% below 60rem and the plate caption fades in only from 45–60% of the timeline (`plate-meta` keyframes + `--progress` clamp), so no two text layers are ever visible together while a plate enters; `--hero-shade-min` 0.22 → 0.32 and the stacked backplate reaches veil-strong at 16%, giving the hero name a measured 5.63:1 worst true-background pixel at 320/375 (AA halo excluded). Evidence in `self-check/probe-p12-overlap-and-hero-shade.txt` and `probe-hero-name-contrast-after-fix.json`.

Two deviations from the lock, both deliberate:
- **Hero name clamp** is `clamp(4.5rem, min(15vw, 22dvh), 13.5rem)` instead of `clamp(4.5rem, 17vw, 15rem)`. With the credentials line, role, lede, CTA and provenance caption that narrative-content placed in the hero, 17vw pushed the credentials above the fold at 1280×800 (probe: creds y = −33). The dvh term keeps the whole hero composition inside the fold (creds y = 104, CTA bottom 687, caption bottom 756 at 1280×800; name 176 px, still 1.5× the largest word pair at 115 px and the heaviest weight on the page).
- **Nav CTA hidden below 26rem (416 px)** so the pill stays content-sized at 320 px; the hero CTA and the menu's Contact link cover it.
